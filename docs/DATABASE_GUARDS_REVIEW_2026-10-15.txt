FINDINGS
1. Original self-account text guard could be bypassed by changing memory_type first. Added immutable type and provenance for existing self-accounts.
2. INSERT OR REPLACE bypassed UPDATE guards and could replace a user-authored row. Added an existing-id insertion guard and immutable ids. The installer refuses secondary UNIQUE indexes until their replacement-conflict behavior is reviewed.
3. Structured context could reattribute a self-account. Added author/subject protection while preserving status/rejection metadata updates.
4. The original transaction demonstration tested standalone SQL, not production save paths. Production librarian tagging happened after shelf commit and swallowed errors. Stores now explicitly begin a transaction, write the memory/affect/context/configured librarian memberships, and commit together. Strict tagger errors roll back that unit. Ring and embedding writes remain separate. An entirely absent librarian index is treated as unconfigured; a partially present schema is an error.
5. The original harness assumes specific live record IDs/states, accepts broad exceptions for rollback, only performs a no-op context update, and does not return a failing exit status when checks fail. Its timing measures total update latency, not incremental trigger overhead. These limitations were sent to Aelen, who was assigned experiment harness/documentation revisions; no response has arrived.

INSTALLATION AND LIMITS
The migration is explicit, not called by get_db or startup. cama/core/db_schema.py is a diagnostic dump, not a schema installer. No live memory records or guard schema were changed by this review. No commit/push or server restart was performed. Existing unrelated checkout changes were preserved.
For an authorized deployment, first make a verified SQLite backup, then run from the repository: .venv/Scripts/python.exe -m cama.core.memory_guards PATH_TO_DATABASE --apply. Reload MCP processes to load Python save-path changes. Installation will refuse an active caller transaction, a changed checksum for this version, or unreviewed secondary UNIQUE indexes.
These triggers protect ordinary DML updates, not an administrator able to drop triggers, delete/reinsert rows, or rewrite audit tables. They do not authenticate who submits a new user teaching. Authorized provenance repair needs an explicitly reviewed maintenance transaction, not a general bypass flag. A narrowly scoped maintenance tool was not added.
